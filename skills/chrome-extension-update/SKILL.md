# Chrome 解压扩展更新

先确定用户要**在原目录更新**还是**切换实际加载目录**。扩展卡片显示版本相同也可能来自两个目录。以 Chrome 的安装详情和启用状态判定结果。

## 确认对象与候选

1. 核对 Chrome 配置文件、扩展名称、版本、ID、启用状态和详情页的「加载来源 / Loaded from」。先确定它是解压扩展。商店或组织托管扩展沿原渠道办理，保留其更新和管理方式。
2. 核对目标目录根部的 `manifest.json`、期望版本、引用的文件及权限变化。按项目方式检查源码或打包产物，有构建步骤时选实际可加载的输出目录。更新已加载目录的文件时，保留受影响文件的可恢复版本及原安装状态。
3. 通过 OCU 使用准确的浏览器进程和窗口，按宿主规则走后台控制。先读当前控件，再执行语义动作。保留人工标签、草稿和前台焦点，只关闭任务创建的临时标签。需要临时标签时，使用宿主支持的定向入口。macOS 上若当前工具支持 `sky_key_event`，优先用它发送本任务标签的组合键，并读回实际焦点和窗口归属。

## 原目录更新

1. 将验证过的文件更新到 Chrome 实际加载的目录。在 `chrome://extensions/` 按 ID 找到原扩展，点卡片的「重新加载 / Reload」。
2. 读回同一个 ID、期望版本、原加载路径和应有的启用状态。检查此次更新是否出现加载错误，再按下方规则验收目标页面。
3. 加载失败时先检查当前卡片、错误和路径。需要回滚时，在授权内恢复受影响文件，再对同一条目重载和验证。

## 换目录

1. 对照原条目和新目录。无固定 manifest 公钥时，解压扩展的 ID 由路径派生。若新旧 ID 不同，按扩展 ID 保存的设置、状态及授权需要单独判断和验证。
2. 记录所有受影响条目的 ID、加载路径和启用状态。用户要单一启用副本时，先停用旧条目并读回。保留旧条目和目录作为回滚点，删除、移除或迁移设置仅按相应授权处理。
3. 如果目标路径已有条目，使用该条目，按需重载并启用。如果尚未登记，在 `chrome://extensions/` 使用「加载已解压的扩展程序 / Load unpacked」。开发者模式关闭时，在授权内启用并读回。若管理策略禁止加载，或出现超出任务授权的权限确认，按第 5 步恢复受影响条目并记录阻塞。用 OCU 进入实际的 manifest 根目录，读回当前位置后按一次「选择 / Select」。
4. 核对目标 ID、版本、启用状态及此次加载错误。在详情中读回完整加载来源。用户要求只启用新版时，确认旧来源已停用且同一 Chrome 配置文件中仅目标副本启用。有固定公钥而共用 ID 时，以详情页的路径和实际条目数为准。再按下方规则验收目标页面。
5. 切换失败时，先按下方规则处理本任务弹窗并核对目标路径是否已注册或启用。若新路径的副本确实已启用，先停用并读回。在当前授权内恢复原路径及原启用状态；若同 ID 条目已被替换，用保留的旧目录重新加载。若 Chrome 拒绝重复 ID，恢复原条目并记录冲突。核对回滚后的 ID、路径和启用状态。

## OCU 目录选择与对账

- macOS 目录选择器通常附着在 Chrome 窗口上。先确认当前面板和焦点，再操作控件。若快捷键落到浏览器主界面，改用选择器自己的侧栏和文件列表。用 OCU 查询精确目录名，发现实际支持的 `Open` 辅助动作时，逐级进入并读回「位置 / Where」。
- 原生辅助动作可能返回错误但目录已经改变。遇到错误、超时或观察中断时，先读取同一目标窗口。选择器仍打开且当前位置是预期根目录，可以按「选择」；若在其他已知目录，从实际位置继续。选择器已经关闭时，核对是否有加载错误以及卡片的路径和启用状态，再决定重试或回滚。需要恢复卡片操作时，只关闭本任务留下的弹窗。状态仍不明或安全后台入口不可用时，停止写入并报告未完成项。

## 验收回执

涉及内容脚本时，在重载或切换后重新打开或刷新获准的目标页面，核对受影响的最小行为。记录浏览器配置文件、安装来源、版本、实际 ID、新旧启用状态、页面行为与未验证项。源码、打包、隔离浏览器测试、日常 Chrome 安装和页面验收分别举证。
