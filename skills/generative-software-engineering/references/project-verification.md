# 项目验收地图

在验收入口反复摸索或存在多个真实用户入口时，将已验证方法维护在项目已有验收技能或文档中。只有没有合适归属时才创建项目技能；不为每个功能生成一套新框架。项目地图实例化 GSE 的证据要求，不降低实际安装版、设备、持久化或跨端验收标准。

## 从项目事实生成

读取项目规则、启动命令、已有测试和受支持控制面。核实真实用户表面、版本身份、操作入口、可观察结果、必要凭据／数据前提及资源 owner。复用现有脚本和官方接口；缺少控制能力先修复或协调，不因为生成器可以选择 CDP、AppleScript 或私有数据源就绕过项目路由。

地图应包含以下可执行信息，可使用 [地图模板](feature-map-template.md)：

- 启动／连接：实际命令或官方入口，目标环境与版本确认。
- 操作前检查：这个实例是否正确且可操作，权限／账号和共享资源是否符合当前授权。
- 用户旅程：入口、操作、可见结果，以及持久化／异步／跨端读回；为同一功能列出有差异的入口。
- 证明：预期值、失败／恢复路径、证据路径和候选身份。不得只写“看起来正常”。
- 清理与现场：只释放本次创建的进程与数据，保存证据，保留用户正常运行环境。

地图里的动作不产生发送、付款、删除、新增权限或新账号授权。使用受控数据和环境；所谓 dry-run 必须核验实际跳过的副作用。不可用的账号、设备或入口写明具体前提，不能填假命令或用假数据冒充现场。

## 执行与覆盖

生成或修改后实际运行它描述的操作。可先用一个代表功能验证操作方法，但只能证明这条方法；当前任务所有受影响入口仍需分别完成。未执行项保留“未验／阻塞”，不能把地图存在、检查命令通过或一次截图算成全部完成。

每条验收记录绑定候选／版本、入口、执行时间、动作、预期与实际结果、证据和状态。由用户表面发起真实操作；内部 setter、mock 和 test-only endpoint 只提供其所属层的证据。保存类功能需在适用时刷新、重启或从另一真实消费端读回。

完成后核对清理没有删除证据。新入口、行为或版本变更只更新相关路径；过时条目标为待更新，修正并执行后恢复可用，不整图复制到全局规则。维护地图不自动创建定时任务。
