# 旧项目／屎山代码全面清理

用户说“用 GSE 清理这个陈旧项目”“屎山代码清理”“全面精简优化并给 Git 瘦身”时使用。目标是让现役项目更小、更清楚、更容易验证和交付，贯通需求、架构、代码、测试、部署及仓库。清理范围不是仅最近修改的函数；减少文件、行数或测试数量本身不是成效。

这是 GSE 自有的跨产物工作流。具体简化、调试、架构、影响分析、评审和验证方法仍从[当前技能路由](skill-routing.md)读取，不复制方法或另建总控框架。

## 先确定实际结果与现场

- 仅要求方案／审计：交付有依据的决策清单与执行方案，不修改业务代码。已明确要求清理实施：审计后持续完成获准的删除、重构、验证、集成及实际交付，不停在建议或 PR。模糊的“一句话”沿原请求和现行授权判断，不把技能当作新增授权。
- 检查项目规则、规范 checkout、Git 状态、在途分支、当前 writer、实际版本与部署入口。保留无关 dirty 和用户运行态；同一索引、源码或交互现场由一人写。现有任务尚未释放时，先完成只读审计与独立技能产物，不新建 worktree 或替代 writer。
- 列出当前必须保持的用户旅程、接口、持久化数据、服务选择、视觉／权限及其他明确决定。旧文件、过时测试或仓库历史不自动构成当前需求；从现行用户决定、真实调用者与运行行为裁决冲突。不能自行把明确要求保留的能力判为废弃。
- 在改动前记录足以比较的基线：跟踪文件／字节、主要复杂职责、依赖与构建入口、测试结果、包体和 Git 对象。按主张取必要指标；不为清理跑全盘扫描、联网付费探测或无决策价值的基准。

## 全面审计与决策清单

每个候选记录：路径／符号、现行职责、过时／冲突／冗余依据、实际消费者、保留／合并／删除／迁移决定、受影响行为、验证和回滚。待确认项明确列出，不能把“暂不动”算完成。

| 层面 | 查什么、收敛到什么 |
| --- | --- |
| 需求与说明 | 被取代或互相矛盾的需求、旧默认值、未落地承诺、重复规则；整理当前产品合同和非目标，指向一个维护正本。必要历史决定用固定提交链接追溯，不让旧方案继续充当指令。 |
| 架构与状态 | 同一事实的多份状态、循环依赖、跨层职责、无用抽象、重复选路、失效兼容和回退；复用现有清晰边界，迁移调用者后删除旧入口，不借清理重写整个产品。 |
| 代码与依赖 | 死代码、孤儿资源、重复实现、占位能力、实验分支、未用依赖及导出；区分静态引用、反射／注册、CLI、配置、脚本及外部消费者。没有文本引用只是线索，不是充分删除证据。 |
| 测试与夹具 | 废弃需求的专属测试、镜像实现或只匹配代码文字的测试、重复场景、过期快照；保留唯一业务回归职责，必要时把保护迁移到行为测试。先核合同再删测试，不降低断言掩盖失败。 |
| 构建与部署 | 多套构建入口、重复打包、失效 CI、环境模板、安装脚本、旧服务定义和遗留配置；本地与 CI 共享有效检查，构建一次验证同一候选，移除调用者后删除旧入口。 |
| 文档与素材 | 重复当前说明、已终止实验、无用导出、过期截图和孤立链接；保留现役用户文档、来源许可、必要决策／效果证据及已公开的稳定入口，删改后核链接与实际呈现。 |
| Git 与存储 | 区分 HEAD 跟踪内容、历史大对象、LFS、refs／tags／reflog、未跟踪运行态与构建缓存；定位体积来源后选择处理，禁止只加 .gitignore 就声称历史已瘦身。 |

## 从方案到实际清理

先形成可审阅方案：当前事实、目标合同、逐项处置、模块归属、依赖顺序、风险、回滚、可观察验收和真实未知。需要架构取舍时使用 `architect`，删除或迁移前以 `blast-radius` 证明关键安全前提，局部简化用 `code-simplifier`，投入与范围用 `avoid-overkill`。实质方案沿 `egm-auto-review` 独立审查，核实并处理发现；不为技能名凑齐全部流程。

按可独立回滚的完整批次执行，先消除已确认冲突和无消费者的闭包，再迁移结构。一次删掉废弃入口、实现、配置、脚本、专属夹具和过时说明，并更新真实调用者；不能留下新旧两套默认路径。仍需兼容的持久化或外部接口写清消费者与退出条件，不无限叠加兼容层。

在每批中保持一个写入负责人。旧异步任务、后台服务和已安装版本都可能是消费者；未知副作用先对账。用户数据／凭据／录音／词库与仓库可丢弃生成物分开，清理不自动包含删除用户数据、缓存或历史资源。存储格式变更须说明前后读取与回滚策略，不能用 revert 源码冒充数据恢复。

## Git 瘦身的准确边界

- 删除现役树内确认无用的跟踪产物，并修正生成目录及忽略规则；已存在历史中的对象不会因此消失。保留实际发布素材与依赖锁文件，不为追求体积删除可重现构建依据。
- 只在当前仓库无并发 Git writer、备份／恢复需求已核对时进行适当的本地压缩。例如仅增量压缩的 `git repack -d`（不加 -a/-A）会移除已有打包副本的冗余存储；执行前核当前 Git 文档与配置，前后核全部对象 ID、refs、reflog 和 worktree 元数据不变，并验证对象完整。`gc --no-prune` 仍可能过期 reflog，不能当作保护恢复历史的保证。准确区分本地压缩、工作树减少和远端历史变化。
- 历史重写、强推、删除分支／tag、清空 reflog 或 prune 恢复对象，依对应明确授权办理。先准备精确对象与 refs 范围、备份／恢复位置、协作者和发布链接影响及测得收益，再请求真正缺少的授权；不让其阻止独立获准清理。
- 小仓优先减少维护负担，不默认导入 LFS、迁仓、浅克隆或定时清理。不能以“零垃圾”为目标回收不属于当前任务的历史资源。

## 验证与交付

复用有效基线，每批核剩余引用、配置兼容、行为回归、链接和构建／安装入口。按风险执行项目必需检查；改变产品行为、生命周期或交互时，验收真实安装／部署版本的受影响旅程，保留正常运行态。只动文稿或死代码不机械扩成全部外部服务测试；付费端点、认证挑战与用户明确暂停遵各自边界。

交付包含：当前产品合同、已审查方案、逐项实际处置及未完项、提交／PR／安装版本、前后可比指标、实际验证与最终运行状态。文件数、行数、Git 本地体积、包体、耗时与用户结果分别报告；未测不写收益，未实施不说清完。按 `verification-before-completion` 核完成主张，沿现行项目规则完成提交、审查、合并与部署。

可复用调用语句：

```text
用 GSE 全面清理这个陈旧项目：审计并清除过时、冲突、冗余的需求、架构、代码、测试、文档、依赖和部署文件，精简有效主链并给 Git 仓库瘦身。先形成有证据、经独立审查的完整方案，再在已有授权内实施、验证并交付；保留仍需支持的能力、用户数据和在途改动，准确列出未完成项。
```
