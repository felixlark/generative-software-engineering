# 性能结论核验

用于根据性能数字做选型、优化决定或报告回归。先写准备声称的结论、单位、数据规模、用户等待的起止边界和正确性条件，再读测量脚本：计时覆盖什么、忽略什么、真正执行了哪些工作。

## 先确认数字有意义

- 工作执行：计时区域内请求已到达、任务已 await／消费、写入已完成、结果确被使用。未迭代的生成器、立即返回的排队请求或超时不能算完成吞吐。
- 正确性：统计成功、错误、拒绝、重试及超时，验证输出内容与数量。快速失败不是提速；错误率不能藏进平均时间。
- 同等条件：两侧使用可比的数据、版本、构建模式、配置、并发、批量和缓存状态。交错执行减少机器负载与预热偏差。配置差异可以成为所测对象，但不能把它称为实现或模型本身的优势。
- 瓶颈与合理性：通过单独的诊断运行识别主要限制，不把 profiler 开销混入成绩。用资源上限和被优化部分的时间占比检查不可能的收益；工具选择适配当前 OS，不照搬 Linux 命令到 macOS。

选型应先让各方案达到合理可比的运行条件。无法公平配置或无法确认正确性时，结论为无法判定；指出具体缺口，不选择赢家。

## 重复性与用户影响

先进行少量交错重复，观察波动；选择与风险相称的样本量，接近噪声的差异继续取样或判为未测出区别，不机械规定所有任务跑固定次数。报告实际样本数、中心值和离散范围；不要把各轮 p50 的中位数混称所有请求的 p50。

同时检查真实端到端路径。微基准只能说明对应部件，说明它占全流程的比重，不能按同一百分比外推用户收益。用户只问大致量级时可给单次观测，但仍要核对正确性和工作执行，并明确不能据此做可靠选型。

## Agent／技能流程比较

固定原始任务、候选基线、模型／强度、权限、工具和成功标准。候选只收到自然任务与所需材料；评分标准和预期缺陷由评估者保存，避免泄题。比较可串行完成，不要求新 worktree；使用允许的隔离临时目录，且不得绕过真实验收。

记录全部参与者的输入 token、缓存输入、输出、模型调用、工具调用、重试、交接、墙钟时间和结果质量；缓存通常是输入的子集，不重复相加。所有失败尝试都计入成本。无法取得的字段标未知，不能拿字符、文件大小或 Agent 自述代替运行时用量。模型／强度由受支持接口或事件核验。

有质量差异时先解释差异，不用更低成本掩盖未完成。小样本只支持所测任务上的观察；总 token、实际费用、额度消耗和墙钟时间分别表述，没有定价／计费证据就不推算费用或宣称节省。

报告结论为更快、更慢、未测出区别或无法判定，并附实际条件、正确性、工作量、样本和证据。完整数据放任务产物，不将临时日志纳入技能源码。方法来源见 [来源说明](method-sources.md)。
