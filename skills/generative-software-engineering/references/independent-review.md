# 独立审查

用于数据完整性、并发、权限、迁移等高风险修改，难以自证的设计争议，或用户明确要求的审查。局部低风险改动优先由当前 Agent 做相称检查。

## 建立独立输入

先固定需求、允许的副作用、候选提交／文件哈希、相关上下文和可运行入口。审查者只读候选，写入自己的临时证据目录；与实现者共享 checkout 时不得改代码、暂存、安装或发布。文字“只读”不冒充运行时强制沙箱。

交给审查者原始要求、候选、必要上下文及统一标准：行为正确性、数据与权限边界、外部兼容、并发／失败恢复、可维护性和验证缺口。不要先告诉它实现者的结论或期待发现的缺陷。相关原始测量／日志可以提供，但与解释分开。审查者不能因提交信息宣称“已修复”而省略核验。

一次独立审查通常足够。只有风险、争议或用户要求支持额外成本时才启用多个审查者。沿用已确认的模型；确需多模型时通过官方能力核实可用型号和强度，按当前选择执行。同模型独立上下文应明确称为独立审查，不称模型多样性。不可用时报告实际覆盖，不静默换 provider 或提升强度。

## 用证据裁决

每个发现给出候选位置、违反的需求、触发条件、可观察后果及验证方式。尽量运行真实实现证明关键问题；无法运行时明确证据层级，不虚构复现或概率。

主 Agent 去重后逐项裁决：

- 必须修复：已证实且影响当前目标／合同。
- 待验证：有依据的疑点，最小实验可解决；不要自动改代码。
- 可选改进：收益与实现代价由当前范围决定。
- 驳回：给出反证或不适用的具体约束。

多模型同意不能代替复现，单个审查者发现的严重真实缺陷也不能因票少被忽略。审查输出本身不自动授权修复：只读评审返回结论；已授权开发则由实现 owner 修复，验证原失败路径和受影响回归。候选改变后重验失效结论，不机械重跑全部审查。

回传实际审查者／模型、候选、可行动发现、裁决及证据限制。新增审查时间与所有参与者 token 计入任务成本；缺少子代理用量时标不完整，不报告虚假的总节省。方法来源见 [来源说明](method-sources.md)。
