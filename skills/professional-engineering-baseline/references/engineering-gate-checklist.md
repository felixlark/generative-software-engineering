# Engineering gate checklist

在大型任务开始时复制为任务中的简短清单；小型局部任务只勾选适用项。

## Before editing

- [ ] 原结果、验收入口、目标环境和失败条件已写清。
- [ ] `git status` 已核；无关 dirty 内容已保留。
- [ ] 已 fetch 规范远端；任务从项目声明的集成 ref 的准确 SHA 建立。
- [ ] 写入现场符合项目隔离政策；base SHA、writer、dirty WIP 归属已记录。
- [ ] 实际 writer、共享资源键和依赖已确认。
- [ ] 变更范围、非目标和必须保持的合同已写清。

## During implementation

- [ ] 一个任务只改一个连贯结果；没有无关重构夹带。
- [ ] 现有实现、标准库、官方 API 和项目惯例已检查。
- [ ] 接口、消费者、数据、迁移、文档和测试按实际影响同步。
- [ ] 测试成本明显时，已定义影响闭包并选择本次迭代、合并前和发布前各自需要的检查。
- [ ] 没有静默错误、无依据重试/回退、吞异常或测试专用分支。
- [ ] 提交可审，提交信息说明结果而非活动量。

## Before review / merge

- [ ] 已在项目声明的集成基线 rebase，并重新运行受影响检查。
- [ ] 已验证原失败或目标行为，不只验证 happy path。
- [ ] 共享合同有全部消费者证据；数据/迁移有旧/新版本矩阵。
- [ ] 依赖变化有 lockfile、来源、漏洞和许可证证据。
- [ ] 行为变化有可复读审查记录；高风险变化有独立专项评审。
- [ ] 复用的旧测试结果与当前源码、依赖、工具链、宿主、fixture 和环境输入仍相同。
- [ ] PR 记录准确 base/head、验证命令、未覆盖项、发布单元和回滚。
- [ ] 合并前 head 与审查、测试使用的 head 相同。

## Before release / install

- [ ] 制品来自项目声明的集成/发布 ref 中已合入且可读回的准确 commit。
- [ ] 构建可复现，签名/摘要和 manifest 已验证。
- [ ] build 单调；candidate/降级已显式标记并记录理由。
- [ ] 安装只由单一 writer 执行，有互斥、进度和失败恢复 receipt。
- [ ] 已明确回滚、前向修复或数据补偿方式。
- [ ] 正式安装后有真实入口、健康、用户旅程和未覆盖项的证据。
- [ ] 正式发布或安装已从干净来源执行项目要求的完整回归，未用局部受影响检查替代。

## At closure

- [ ] `patch_ready`、`integrated_preview`、`released`、`accepted` 分开陈述。
- [ ] evidence 绑定最终候选或最终运行态。
- [ ] 未完成项、风险、owner 和下一动作清楚。
- [ ] 自建且已合并、干净、无进程的 worktree 已回收。
- [ ] branch、dirty/unknown 现场和临时资源按项目规则保留或交接。
